# Skills 管理工具 PRD（细化评审版）

**版本：** V1.1 Confirmed Draft  
**产品形态：** Tauri + Rust 跨平台桌面应用  
**文档状态：** 待产品与技术评审  
**作者：** Manus AI

## 1. 文档目的

本文档用于将“中央仓库 + 项目内安装 + 软链接挂载”的产品设想细化为可设计、可开发、可验收的 V1 需求。本文对尚未确定的内容明确标注了**默认建议**，并在文末集中列出需要产品方确认的问题。

> **核心原则：** Skill 原件只维护一份；项目只保存指向原件的链接；工具负责发现、安装、检查、修复和记录链接状态，但不接管 AI Coding Agent 的运行时行为。

## 2. 产品定义

### 2.1 产品定位

Skills 管理工具是一款面向个人开发者的本地桌面应用，用于统一管理多个 AI Coding Agent 所使用的 Skill。V1 只管理一个中央 Skill 来源，该来源可以是 Git 仓库或普通本地目录；用户可在不同项目中按需挂载 Skill，并持续查看链接、路径和 Git 状态。

### 2.2 目标用户

| 用户类型 | 特征 | 核心诉求 |
|---|---|---|
| 多 Agent 开发者 | 同时使用 Claude Code、Codex 等工具 | 一套 Skill 在多个 Agent/项目中复用 |
| Skill 维护者 | 维护自建或开源 Skill 仓库 | 集中更新原件，避免重复修改 |
| 项目型开发者 | 同时维护多个代码仓库 | 每个项目只启用必要 Skill，避免全局污染 |

### 2.3 用户痛点

当前用户通常需要手动复制目录、记忆多个 Agent 的约定路径，并自行判断哪些目录是原件、哪些是副本。由此容易出现重复安装、版本不一致、软链接断裂、误删原件和项目配置不可追溯等问题。

### 2.4 产品目标

| 目标 | 可衡量结果 |
|---|---|
| 降低首次配置成本 | 新用户在 5 分钟内完成首次仓库扫描、项目添加和 Skill 挂载 |
| 降低 Skill 维护成本 | 更新中央仓库后，无需逐项目复制文件 |
| 提升状态可见性 | 用户能够明确区分正常、断链、冲突、未托管和权限错误 |
| 降低误操作风险 | 卸载只删除工具创建的链接，不删除中央仓库原件或用户未知文件 |
| 支持主流平台 | macOS、Linux、Windows 具备同等核心能力；平台限制需要明确提示 |

### 2.5 V1 非目标

V1 不负责编辑、生成、测试或执行 Skill 内容；不替代 Claude Code、Codex 等 Agent；不提供云同步、团队协作、账号体系和在线 Skill 市场；不自动修改项目源码或 Agent 配置文件，除非用户明确确认创建链接入口。

## 3. 关键概念与边界

| 概念 | 定义 |
|---|---|
| 中央仓库 | 用户指定的本地目录，可对应 Git 仓库，也可是不含 Git 的普通目录 |
| Skill 原件 | 中央仓库中被识别为一个 Skill 的目录及其全部内容 |
| 项目 | 用户添加到工具中的本地代码或工作目录 |
| Agent 目标目录 | 某个项目内用于放置 Skill 链接的目录，例如 `.agents/skills` |
| Skill 挂载 | 在 Agent 目标目录下创建指向 Skill 原件的目录软链接 |
| 入口链接 | Agent 约定目录之间的目录软链接，例如 `.claude/skills` 指向 `.agents/skills` |
| 托管链接 | 由本工具创建并记录了来源、目标和配置指纹的软链接 |
| 冲突 | 目标路径已存在且不是本工具可安全识别和管理的链接 |

**已确认边界：** V1 只支持一个中央 Skills 来源；工具只管理项目内明确配置的目标目录，不主动扫描或修改用户未授权的目录。`.agents/skills` 是唯一实际安装目录，其他 Agent 目录只能作为入口链接配置。

| 模块 | V1 优先级 | 说明 |
|---|---:|---|

| 项目添加、目标目录配置 | P0 | 核心能力 |
| 单个 Skill 安装、卸载 | P0 | 核心能力 |
| 链接状态检测 | P0 | 核心能力 |
| 冲突和断链处理 | P0 | 必须可恢复 |
| Git status / pull | P1 | 首版支持基本操作 |
| 批量安装与卸载 | P1 | 提升效率 |
| 入口链接管理 | P1 | 需明确 Agent 约定 |
| 配置导入导出 | P1 | 用于迁移和备份 |
| 自然语言命令模板 | P2 | 辅助功能，可延期 |

| 工作区自动发现 | P2 | 后续增强 |

## 5. 信息架构与核心界面

### 5.1 页面结构

应用建议采用三栏布局：左侧为仓库与项目导航，中间为当前来源下的 Skill 列表，右侧为当前项目和挂载状态。顶部提供全局刷新、添加仓库、添加项目、设置和操作日志入口。

| 区域 | 主要内容 | 主要操作 |
|---|---|---|
| 左侧导航 | 中央仓库、项目列表、异常数量 | 切换仓库、切换项目 |
| 中央列表 | Skill 名称、描述、来源、更新时间、选中状态 | 搜索、过滤、多选、查看详情 |
| 右侧详情 | 当前项目、目标 Agent、已挂载 Skill、状态 | 安装、卸载、修复、打开目录 |
| 顶部工具栏 | 刷新、Git 更新、设置、日志 | 全局级操作 |
| 底部反馈区 | 最近操作、错误、恢复建议 | 查看详细日志 |

### 5.2 状态颜色与文案

颜色不能作为唯一信息载体，状态卡片同时显示文字和可操作建议。

| 状态 | 含义 | 建议操作 |
|---|---|---|
| 正常 | 链接存在，目标匹配，来源可访问 | 无需操作 |
| 断链 | 链接存在但目标不存在或不可访问 | 重新扫描、修复或卸载 |
| 指向错误 | 链接目标存在，但不是登记的 Skill 原件 | 查看详情、重新绑定 |
| 冲突 | 目标被普通文件或目录占用 | 备份后替换、跳过或取消 |
| 未托管 | 目录存在但不是工具创建或登记的对象 | 导入、跳过或删除 |
| 权限错误 | 当前用户无法读取、创建或删除目标 | 查看权限说明、重试 |
| 未检查 | 尚未完成扫描或状态未知 | 刷新状态 |

## 6. 功能需求

### 6.1 中央仓库管理

#### 6.1.1 添加仓库

用户可以通过“选择本地目录”添加仓库，也可以输入 Git URL 并选择本地克隆目录。添加完成后，系统验证目录是否存在、是否可读，并立即执行一次扫描。

**验收标准：**

1. 本地目录不存在、不可读或不是目录时，阻止保存并展示明确原因。
2. Git URL 为空或格式明显不合法时，阻止提交；网络、认证或目标目录错误时，保留可重试状态。
3. V1 只允许登记一个中央来源；已登记路径不能重复添加。
4. 添加完成后展示仓库名称、路径、是否 Git 仓库、当前分支或提交信息。

#### 6.1.2 Skill 扫描

扫描器 V1 仅扫描中央仓库根目录下的 `skills/` 目录：

```text
central-repo/
├── skills/
│   ├── skill-a/
│   │   └── SKILL.md
│   └── skill-b/
│       └── SKILL.md
└── other-content/
```

仅将 `skills/` 目录下直接包含 `SKILL.md` 的子目录识别为 Skill。Skill 名称优先取目录名，描述优先读取 `SKILL.md` 的 frontmatter 或首段摘要。无法解析元数据时仍显示 Skill，但标记为“元数据不完整”。V1 不扫描仓库根目录下的其他目录，也不支持自定义扫描规则。

扫描结果至少包含：Skill 名称、相对路径、绝对路径、描述、来源仓库、最近文件更新时间、Git 是否有未提交变更、解析状态和唯一标识。

#### 6.1.3 Git 操作

V1 支持查看 Git 状态、拉取远程更新、刷新扫描结果。中央来源可以是 Git 仓库或普通本地目录；普通本地目录不显示 Git 状态、pull、分支或 tag 操作。所有 Git 操作必须限定在用户登记的中央仓库目录内，并在日志中记录命令类型、开始时间、结束时间、结果和错误摘要。私有仓库认证沿用系统 Git 的 SSH Key、Credential Helper 等机制，应用不保存 Token 或 SSH 凭据。

**默认策略：** 若工作区存在未提交修改，点击“更新”前先警告用户；V1 默认不自动 stash、不自动 reset、不自动切换分支。用户取消后不执行任何破坏性操作。

### 6.2 项目管理

用户可以通过目录选择器添加项目，也可以手动输入路径。项目保存后，用户可以配置多个 Agent，但所有 Agent 均共享唯一的实际安装目录 `.agents/skills`；其他 Agent 目录只能配置为指向该目录的入口链接。

| 配置项 | 示例 | 必填 |
|---|---|---:|
| 项目名称 | `my-app` | 否，默认取目录名 |
| 项目路径 | `/Users/me/code/my-app` | 是 |
| Agent 类型 | Claude Code / Codex / 自定义 | 是 |
| 实际 Skill 目录 | `.agents/skills` | 是，V1 固定为该目录 |
| 入口链接 | `.claude/skills` → `.agents/skills` | 否，可配置多个 |
| 链接类型 | 相对 / 绝对 | 是，V1 默认相对链接 |

项目列表应显示路径、配置的 Agent 数量、已挂载 Skill 数量和异常数量。项目被移除时只移除工具中的登记，不删除项目目录、Skill 链接或入口链接，除非用户在明确确认框中选择“同时清理本工具创建的链接”。

### 6.3 Skill 安装与卸载

#### 6.3.1 安装

用户在中央仓库中选择一个或多个 Skill，选择目标项目和 Agent 配置后点击“安装”。系统依次执行路径校验、来源校验、冲突检查、临时链接创建、目标验证、登记持久化和结果反馈。

安装规则如下：

1. 目标父目录不存在时，允许创建缺失目录，并在日志中记录。
2. 目标路径不存在时，默认创建相对目录软链接。
3. 目标路径已是指向正确原件的链接时，视为幂等成功，不重复创建。
4. 目标路径是指向其他位置的链接、普通文件或目录时，进入“备份后替换”流程；用户必须显式确认，不能静默覆盖。
5. 用户确认替换后，先将原对象移动到带时间戳的备份目录，再创建新链接；用户也可以选择跳过或取消。
6. 中央仓库原件不存在、不可读或路径不在登记仓库范围内时，阻止安装。
7. 批量操作部分失败时，展示逐项结果，并提供“回滚本批次已成功项”的选项。

#### 6.3.2 卸载

卸载默认只删除目标项目内、且能够确认由本工具管理的 Skill 软链接。卸载前展示项目、Agent、Skill、链接目标四项信息。任何情况下不得根据名称直接删除中央仓库原件。

如果链接无法确认是否由本工具创建，系统应显示“未托管对象”，默认不删除；用户可以通过“强制删除链接”执行，但必须再次确认，并明确说明不会删除链接目标内容。

#### 6.3.3 入口链接

入口链接是独立于 Skill 链接的配置对象。系统应允许用户配置多个入口链接，例如 `.claude/skills`，但实际安装始终只发生在 `.agents/skills`。系统应允许创建、检查、修复和删除入口链接，并明确展示“删除入口链接不会删除 `.agents/skills` 中的 Skill 链接”。入口链接目标已存在时，必须先检测其类型和指向，禁止静默覆盖。

### 6.4 状态检测与修复

状态检测既支持用户手动刷新，也支持进入项目时自动执行。检测不应修改文件系统。

| 检测项 | 判断规则 |
|---|---|
| 来源存在 | 中央仓库和 Skill 原件仍存在且可读取 |
| 链接类型 | 目标是目录软链接，而非普通目录或文件 |
| 指向匹配 | 解析后的真实路径与登记的原件路径一致 |
| 路径安全 | 目标路径未越界到未授权项目目录 |
| 入口有效 | 入口链接指向配置的 Agent 目标目录 |
| 元数据一致 | 当前链接与本地登记的仓库、Skill、项目关系一致 |

修复操作必须针对具体问题提供动作：断链可“重新创建链接”或“卸载登记”；指向错误可“重新绑定”或“跳过”；冲突可“备份后替换”“跳过”或“取消”；权限错误可“重新授权后重试”。

### 6.5 搜索、过滤与详情

Skill 列表支持按名称、描述、仓库、状态和是否已挂载过滤。详情页展示 Skill 的目录结构摘要、`SKILL.md` 元数据、来源仓库、当前 Git 分支、原件路径和已挂载项目清单。V1 不在应用内编辑 Skill 文件，但允许通过系统文件管理器打开原件目录。

### 6.6 配置导入导出

导出文件只保存路径、仓库、项目、Agent 配置、挂载关系和应用版本，不复制 Skill 原件。若中央来源为 Git，还需保存 Git remote、当前分支和 tag 信息，但不保存任何认证信息。导入时先执行预览和路径映射，逐项展示“路径存在、路径缺失、Skill 缺失、需要重新扫描”等状态；Git 信息仅作参考，必须重新验证本地路径、remote 和仓库状态。用户确认后才写入本地配置。

### 6.7 操作日志

日志至少包含操作时间、操作类型、操作者（本地当前用户）、仓库路径、项目路径、Skill 名称、目标路径、原目标、结果、错误码和用户可读说明。日志支持按时间、项目、状态和操作类型过滤，并支持复制错误详情；V1 可不提供远程上报。

## 7. 核心流程

### 7.1 首次使用

```text
启动应用
  → 检测本地配置
  → 无配置时进入引导
  → 添加中央仓库
  → 扫描并展示 Skill
  → 添加项目
  → 选择 Agent 目标目录
  → 选择 Skill
  → 检查冲突
  → 创建软链接
  → 验证并展示成功结果
```

### 7.2 日常更新

```text
选择中央仓库
  → 查看 Git 状态
  → 用户确认拉取更新
  → 执行 git pull
  → 重新扫描 Skill
  → 检查受影响挂载
  → 展示“原件已更新，链接无需重建”
```

若 Skill 目录被删除、移动或重命名，系统不得直接将其视为正常更新，而应将相关挂载标记为断链或来源变更。系统提供统一确认入口，用户确认后才批量清理相关项目链接；未确认前不得自动删除。

### 7.3 冲突处理

```text
发现目标路径已存在
  → 展示对象类型、路径和风险
  → 备份后替换 / 跳过 / 取消
  → 若替换，先移动到带时间戳的备份目录
  → 创建新链接
  → 验证成功
  → 记录原路径与备份路径
```

备份目录必须位于用户可见位置，并提供打开目录和恢复说明。若软链接创建失败，用户可选择 Windows Junction 或复制模式；复制模式必须标记为“独立副本”，并提示其不会随中央原件自动同步。

## 8. 数据模型建议

建议使用 SQLite 保存结构化配置和操作记录；Skill 扫描结果可缓存，但必须能够从文件系统重新生成。

### 8.1 主要实体

| 实体 | 关键字段 |
|---|---|
| Repository | id、name、path、source_type、git_remote、current_branch、last_scanned_at |
| Skill | id、repository_id、name、relative_path、canonical_path、description、metadata_status、content_hash、last_seen_at |
| Project | id、name、path、last_scanned_at、is_archived |
| AgentTarget | id、project_id、agent_type、install_dir（固定为 `.agents/skills`）、entry_link_paths、link_mode |
| Mount | id、skill_id、agent_target_id、link_path、resolved_target、mount_mode（symlink/junction/copy）、status、managed_by_app |
| OperationLog | id、operation_type、entity_type、entity_id、status、error_code、message、created_at |
| AppSetting | key、value、updated_at |

### 8.2 关系约束

V1 只有一个 Repository；该 Repository 可以包含多个 Skill。一个 Project 可以配置多个 AgentTarget，但所有 AgentTarget 共享唯一的 `.agents/skills` 实际安装目录，并可配置多个入口链接。一个 AgentTarget 可以关联多个入口链接；同一项目下的 Skill 挂载记录以 `.agents/skills/<skill-name>` 为唯一目标。挂载模式必须记录为 symlink、junction 或 copy。

路径应统一进行规范化和真实路径解析，比较时处理相对路径、大小写差异、路径分隔符和符号链接解析结果。删除数据库记录前应保留操作日志，并优先采用软删除或归档状态。

## 9. Rust Command 接口建议

以下接口用于前后端边界设计，实际命名可在技术评审后调整。

| Command | 输入 | 输出 |
|---|---|---|
| `repository_add` | 本地路径或 Git URL、克隆目标 | Repository、扫描摘要 |
| `repository_scan` | repository_id | Skill 列表、扫描警告 |
| `repository_git_status` | repository_id | 分支、提交、变更文件、错误 |
| `repository_git_pull` | repository_id、确认参数 | 拉取结果、受影响 Skill |
| `project_add` | 项目路径、名称 | Project |
| `agent_target_upsert` | project_id、Agent 配置 | AgentTarget |
| `skill_mount` | skill_ids、agent_target_id、冲突策略 | 逐项 MountResult |
| `skill_unmount` | mount_ids、强制参数 | 逐项 UnmountResult |
| `mount_scan` | project_id 或 agent_target_id | 状态列表 |
| `mount_repair` | mount_id、修复策略 | RepairResult |
| `entry_link_create` | agent_target_id、冲突策略 | EntryLinkResult |
| `config_export` | 输出路径 | 文件摘要 |
| `config_import_preview` | 输入路径、路径映射 | 预览结果 |
| `operation_log_query` | 过滤条件、分页 | 日志分页数据 |

后端返回统一的错误码和面向用户的说明，前端不得通过解析自然语言错误判断业务分支。

## 10. 错误码与用户提示

| 错误码 | 场景 | 用户提示与建议 |
|---|---|---|
| `PATH_NOT_FOUND` | 路径不存在 | “路径不存在，请重新选择目录。” |
| `PATH_NOT_READABLE` | 无读取权限 | “无法读取该目录，请检查权限后重试。” |
| `TARGET_CONFLICT` | 目标已被占用 | “目标路径已存在，未执行覆盖。” |
| `BROKEN_LINK` | 链接目标不存在 | “链接已断开，可重新创建或卸载。” |
| `WRONG_TARGET` | 指向错误位置 | “链接目标与登记来源不一致，请重新绑定。” |
| `GIT_DIRTY` | 工作区有未提交修改 | “仓库存在未提交修改，更新前请确认。” |

## 11. 跨平台与安全要求

应用必须使用平台无关的路径 API，禁止通过字符串拼接假设路径分隔符。Windows 创建符号链接失败时，需要区分权限不足、目标类型不支持和路径冲突，并提供平台相关指引。macOS/Linux 同样需要处理权限、只读目录和挂载盘异常。

所有写操作应先进行目标路径校验，确保目标位于用户明确配置的项目目录下；不得跟随未知软链接越界删除文件。删除操作只允许删除已确认的链接本身，不递归删除链接目标。Git 操作只允许作用于登记的中央仓库，不执行仓库中的脚本、钩子或任意 Skill 内容。

在创建或替换链接时，建议采用“校验 → 创建临时对象 → 验证 → 原子替换或回滚”的流程。任何异常都必须记录原始路径、目标路径和已完成步骤，方便恢复。

## 14. 版本规划

### V1 MVP

V1 交付中央仓库与项目管理、Skill 扫描、单个安装与卸载、软链接状态检查、基础冲突提示、日志记录和 Git status/pull。V1 应优先保证“正确、安全、可恢复”，而不是覆盖所有 Agent 目录约定。

### V1.1

V1.1 增加批量安装与卸载、批次回滚、断链和冲突修复、配置导入导出、更多 Agent 预设和更完整的日志检索。Git 分支或 tag 切换不属于已确认的 V1.1 必做项，需另行评估。

### V2

V2 可评估 Skill 元数据编辑、工作区自动发现、预设模板、Skill 依赖关系、版本锁定、多中央仓库、远程仓库目录和团队协作能力。

## 15. 已确认决策汇总

以下决策已由需求方逐项确认，后续设计与开发以此为准：

1. V1 面向单机单用户，不做账号和云端同步。
2. V1 只支持一个中央仓库；来源可以是 Git 仓库或普通本地目录。
3. 仅扫描中央仓库根目录下的 `skills/` 目录，其中直接包含 `SKILL.md` 的子目录才识别为 Skill。
4. `.agents/skills` 是唯一实际安装目录；其他 Agent 目录只能配置为入口链接。
5. 默认使用相对软链接；软链接失败时用户可以选择 Windows Junction 或复制模式。
6. `.claude/skills` 等入口链接由用户在 Agent 配置中显式开启。
7. Git pull 默认不自动处理未提交修改，不执行 stash、reset 或分支/tag 切换。
8. 私有 Git 仓库沿用系统 Git 认证，应用不保存 Token 或 SSH 凭据。
9. Git 更新导致 Skill 删除或重命名时，统一确认后才批量清理相关项目链接。
10. 冲突对象允许在用户确认后备份并替换，且必须支持日志记录和失败回滚。
11. V1 不做 Token 上下文预估；仅展示文件数、字符数等客观信息。
12. V1 不自动发现被移动的项目目录；路径失效时标记异常并由用户重新定位。
13. 导出配置包含 Git remote、当前分支和 tag，但导入时只作参考并重新验证。
